# 第二階段設定步驟：Google 試算表 + Apps Script

每一步做完再進行下一步。遇到任何錯誤訊息，把畫面文字貼給 Claude 即可。

---

## 步驟 1：打開 Apps Script

1. 打開球隊的 Google 試算表。
2. 上方選單點 **「擴充功能」→「Apps Script」**，會開啟新分頁。
3. 左邊有一個檔案叫 `程式碼.gs`（或 `Code.gs`），裡面有一段 `function myFunction() {}`。

## 步驟 2：貼上程式

1. 在電腦上打開專案資料夾裡的 `apps-script/Code.gs`（可用記事本開啟）。
2. 全選（Ctrl + A）並複製（Ctrl + C）。
3. 回到 Apps Script，把 `程式碼.gs` 裡原本的內容**全部刪掉**，再貼上（Ctrl + V）。
4. 按上方的 **💾 儲存**（或 Ctrl + S）。
5. 左上角專案名稱可改成「棒球隊 API」。

## 步驟 3：執行 setup()，建立工作表與教練帳號

1. 上方工具列有一個函式下拉選單，選擇 **`setup`**，按 **▶ 執行**。
2. 第一次執行會要求授權：
   - 點「審查權限」→ 選擇你的 Google 帳號。
   - 若出現「Google 尚未驗證這個應用程式」，點「進階」→「前往 棒球隊 API（不安全）」。這是因為程式是你自己寫的、沒有送 Google 審查，屬於正常情況。
   - 點「允許」。程式需要的權限是：讀寫這份試算表、在雲端硬碟建立備份。
3. 下方「執行記錄」會出現：`✅ 已建立教練帳號。帳號：coach　登入碼：XXXXXXXX`
4. **把登入碼抄在安全的地方。** 之後無法再查看（忘記時執行 `resetCoachCode` 重新產生）。
5. 回到試算表，下方會出現 14 個工作表分頁。

> ⚠️ 不要把登入碼貼給 Claude 或任何人。

## 步驟 4：執行自動測試

1. 函式下拉選單選 **`runSelfTests`**，按 **▶ 執行**。
2. 執行記錄最後應該出現 `結果：36 / 36 通過`。
3. 測試會自動建立暫時的測試帳號，測完自動刪除，不會影響正式資料。

## 步驟 5：部署成網頁應用程式

1. 右上角 **「部署」→「新增部署作業」**。
2. 左邊齒輪「選取類型」→ **「網頁應用程式」**。
3. 設定：
   - 說明：`第二階段`
   - 執行身分：**我**
   - 誰可以存取：**所有人**
4. 按「部署」，複製出現的 **網頁應用程式網址**（`https://script.google.com/macros/s/…/exec`）。
5. 把這個網址給 Claude。這個網址不是密碼：沒有登入碼的人呼叫它，只會得到「尚未登入」。

> 為什麼是「所有人」？因為學生不一定有 Google 帳號。資料保護由登入碼與後端權限檢查負責，試算表本身仍然只有你看得到。

## 步驟 6：設定前端（Claude 協助）

Claude 會在專案根目錄建立 `.env.local`：

```
VITE_GAS_API_URL=你的網頁應用程式網址
```

重新啟動 `npm run dev` 後，登入頁就會出現「☁️ 雲端登入」。

## 步驟 7：實際測試

1. 用 `coach` 與你的登入碼登入。
2. 教練後台 → 新增一位球員（可先用測試名字），記下畫面顯示的帳號與登入碼。
3. 體能檢測中心 → 幫這位球員新增一筆紀錄。
4. 登出，用球員帳號登入 → 寫今天的筆記。
5. 打開試算表，確認 `DailyNotes`、`FitnessTests`、`AuditLogs` 有新資料。

---

## 之後修改程式時

在 Apps Script 貼上新版程式後，要 **「部署」→「管理部署作業」→ ✏️ 編輯 → 版本選「新版本」→ 部署**，網址不會改變。

## 重要提醒

- 試算表**不要**設定成「知道連結的人都能檢視」。
- 定期在 Apps Script 執行 `backupNow()` 建立備份（第五階段會設定成每週自動執行）。
- 試算表中 `codeHash` 欄位是登入碼的加密雜湊值，不是登入碼本身，請不要手動修改。
